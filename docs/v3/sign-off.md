## Sign-off: v3 — Desktop Application (Tauri)

Confirmed: success criteria verified
  - Tauri app launches, spawns the Python API as a sidecar, backend-ready event gates the Record button.
  - Push-to-talk and continuous recording produce GPU-accelerated transcription through the Tauri webview (0.8–1.0 s on `large-v3`).
  - Voice commands (`copy`, `clear`) fire with audible confirmation; clipboard writes via the HTTP server on 8001, audio cues via `rodio` on the same port.
  - All three clipboard call sites route through `platform.writeClipboard()` (`App.tsx` voice command, `App.tsx` `handleCopyTranscript`, `Transcript.tsx` button).
  - Continuous-mode segment joins produce correct whitespace (short-gap space, long-gap paragraph break, no prefix on first segment).
  - System tray menu, close-to-minimize with second-close quit, recording-state tooltip, and sidecar cleanup on all three quit paths verified on WSLg at the component level.
  - 169 automated tests green (125 frontend, 44 backend), TypeScript clean, Rust clean. (Note: the v3.4 roadmap entry claims 178 tests; the progress-report total of 169 is accurate for the v3.3 snapshot reviewed here.)

Plan-review trace:

  - **Finding 1 — Bare-host CUDA runtime dependency** → resolved — `cuda_ld_library_path()` in `apps/desktop/src-tauri/src/main.rs:47` discovers pip-installed NVIDIA libraries under `site-packages/nvidia/*/lib/` and injects them via `LD_LIBRARY_PATH` on the sidecar child process (verified: `main.rs:111` `let ld_path = cuda_ld_library_path(api_dir)`). `nvidia-cublas-cu12` listed as a bare-host prerequisite. Progress report Triage #2 documents the symptom, `strings` analysis (two dlopen targets, `libcuda.so.1` and `libcublas.so.12`, no cuDNN), and the two-part fix. GPU inference on bare host is exercised and `/health` returns `device: "gpu"`.

  - **Finding 2 — WebKitGTK `getUserMedia` permission model** → resolved — `main.rs:282` sets `enable_media_stream` (layer 1) and `main.rs:287` connects `connect_permission_request` on the WebKitGTK `WebView` (layer 2, auto-grant). Progress report Triage #4 documents the silent-denial failure mode and names the incomplete fix (layer 1 only) explicitly so it is not repeated. `webkit2gtk = "2.0"` is in `Cargo.toml`.

  - **Finding 3 — MediaRecorder encoder availability** → resolved — `useRecorder.ts:11` exports `negotiateMimeType()`, `useRecorder.ts:111` invokes it, `useRecorder.ts:150` branches to the `ScriptProcessorNode` PCM fallback when negotiation returns null, and `encodeWav` is imported from `../utils/audio` (line 2). Backend 0-byte guard lives in `transcribe_ws.py` with the new `audio_format` query parameter; frontend empty-blob guard lives in `api.ts` on both WebSocket and HTTP paths. Progress report Triage #8 documents all three layers and the 10 new tests (7 frontend for MIME negotiation and PCM fallback lifecycle, 3 backend for `audio_format` suffix and empty payload rejection).

  - **Finding 4 — Tauri clipboard plugin without user activation** → resolved — HTTP clipboard server on `127.0.0.1:8001` lives in `main.rs:296–406` (`tiny_http::Server::http("127.0.0.1:8001")` at line 303, `POST /clipboard` handler writes via `arboard`, `POST /audio/play` handler routes to `rodio`, 204 responses, CORS header for dev origin). `arboard = "3"` and `tiny_http = "0.12"` are in `Cargo.toml`. Progress report Triage #6 documents the plugin crash (`NeedDebuggerBreak` trap), the investigation sequence (`isDesktop()` bug masked the plugin failure until `withGlobalTauri: true` was fixed), and the CSP `connect-src` requirement (`http://127.0.0.1:8001`). Plugin permanently removed from the dependency graph and documented as not-to-retest.

  - **Finding 5 — XGrabKey on WSLg** → open — `Cargo.toml` contains no `global-shortcut` entry (grep confirms). The `tauri-plugin-global-shortcut` crate was added during v3.3 implementation, exercised, and removed after confirming `XGrabKey` registers but never delivers events on WSLg. The frontend event bridge (`shortcut-registration-failed` listener, `tray-toggle-recording` handler) is retained and tested. Re-addition on native Linux is a Rust-only change per the progress report. This is a named deferral, not a silent drop, but it is still an open item against the original v3.3 scope and goes to Open Issues below.

  - **Finding 6 — WebKitGTK keyboard interception** → resolved — Desktop hotkey hints in `App.tsx` display `Ctrl+Shift+Y` and `Ctrl+Shift+X` only when `isDesktop()` is true. WebKitGTK interception of `Ctrl+Shift+Space` (accessibility activation, alternating dispatch) and `Ctrl+Shift+S` (Save As) is documented in `useHotkeys.ts` comments and in the progress report "v3.3 — global shortcut investigation" Principal note. Browser behavior is unchanged. Recording in desktop mode uses the UI button or tray menu.

  - **Finding 7 — Port-conflict and sidecar shutdown fail paths** → partially resolved — Sidecar SIGTERM/SIGKILL pattern is implemented (progress report "Shutdown" section names "Waits up to 5 seconds for graceful exit, then SIGKILL"), which closes the missing-timeout part of the finding. Crash detection via `Child::try_wait()` on each poll cycle is implemented (progress report "Health poll" section), surfacing non-zero exits immediately rather than after the 120-second timeout. The port-conflict dialog *copy* and recovery-action wording were never pinned in scope and I cannot verify them from the progress report text alone. This is a low-severity residual and is flagged as open below.

  - **Finding 8 — CORS / WebSocket origin coverage** → resolved — `config.py` default `CORS_ORIGINS` now includes all four origins: `http://localhost:5174`, `http://127.0.0.1:5174`, `https://tauri.localhost`, `tauri://localhost`. Progress report "CORS" section confirms both `main.py` middleware and `transcribe_ws.py` WebSocket origin check read from `settings.cors_origins` (single-source update). WebSocket streaming through the Tauri webview was exercised during the v3.0 gate session.

  - **Finding 9 — Continuous-mode auto-scroll** → resolved — Auto-scroll pin/release/re-engage behavior shipped in `apps/web/src/features/transcript/Transcript.tsx`, with five tests in `Transcript.test.tsx`. The progress report acknowledges this as scope expansion ("Auto-scroll — this was not in the v3.1 roadmap scope") but the behavior matches the close condition stated in the plan-review finding: pin engages on session start or scroll-to-bottom, releases on scroll-away or manual edit, re-engages on scroll-to-bottom. Accepted as resolved since the Builder identified and closed the gap at the correct point in the delivery sequence.

  - **Finding 10 — v3.3 full-loop gate scenario on WSLg** → partially resolved — Component-level gate verified on WSLg per progress report "v3.3 gate" section: 10 items checked (tray toggle recording, tray settings, tray quit with sidecar cleanup, close-to-minimize, second-close quit, state emission, shortcut registration failure surface, `Ctrl+Shift+Y`/`Ctrl+Shift+X` reliability, rapid-fire debounce, full test suite green). End-to-end gate (global hotkey fires from unfocused app, tray icon renders, window-hidden scenario) explicitly deferred to native Linux. The split-gate tier structure matches the close condition, and the deferral is documented. Residual items are the native-Linux runtime validations themselves, flagged as open below.
